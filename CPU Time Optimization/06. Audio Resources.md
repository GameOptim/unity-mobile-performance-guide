# 2.6 Audio Resources

The memory footprint and runtime performance overhead of audio resources depend mainly on loading mode, compression format, channel type, and sample rate configuration. Improper settings easily lead to memory redundancy, loading stutter, or extra CPU consumption during playback. Targeted optimization is required based on audio type (BGM / sound effect / voice) and device tiering. Key points:

(1) Channel Type Optimization

Prioritize enabling the **Force To Mono** option to automatically mix stereo audio into mono. This setting does not lose core sound effect information but directly halves audio memory usage, making it the most cost-effective optimization for mobile audio.

Reserve stereo only for audio requiring core stereo effects (e.g., 3D spatial sound, surround BGM). All other audio (UI sounds, character voice) should be forced to mono.

(2) Select Proper Loading Mode

Short sound effects (duration < 3 seconds, short and frequently played, e.g., click, collision): use **Compressed In Memory** mode. Audio resides in memory in compressed form and decompresses quickly at playback, balancing memory and performance.

Long audio (duration ≥ 30 seconds, e.g., background music; or 10 < duration < 30 seconds, rarely replayed, e.g., story voice): use **Streaming** mode. Only the header and cached chunks are loaded, keeping memory stably below 200 KB and avoiding memory spikes from one-time loading.

The default **Decompress On Load** mode is generally not recommended, as it fully decompresses audio during loading and causes a sharp memory increase (e.g., a 10 MB compressed audio may exceed 50 MB after decompression).

(3) Compression Format and Quality Adjustment

For audio in **Compressed In Memory** mode, prioritize high-compression formats:

- Android: **Vorbis** recommended

- iOS: **MP3** recommended

  

  Both provide higher compression than Unity default formats, reducing memory usage by 30%–50%.

Adjust the **Quality** parameter for further optimization:

- Non-core sound effects: 50%–70%

- Voice audio: 60%–80%

- BGM: 80%–90%

  

  Actual values should be tuned within acceptable sound quality to maximize compression.

Avoid uncompressed formats such as **PCM** whenever possible. Their memory usage is 5–10 times higher than compressed formats. Use only for short core audio requiring extremely high quality (e.g., key story voice clips).

(4) Sample Rate and Bit Depth Reduction

Mobile audio sample rates are recommended to be set by type, but should also be adjusted based on actual sound performance.

Additional considerations based on actual project conditions:

(1) Audio Resource Reuse and Trimming

Extract common sound effects (button click, item pickup) as shared resources to avoid duplicate similar audio files.

Trim silent segments at the start and end to reduce invalid duration, memory usage, and loading time.

(2) Tiering Strategy Adaptation

High-end devices: retain stereo, high sample rate, and high quality for better audio experience.

Mid-to-low-end devices: force mono, lower sample rate, disable non-core audio (e.g., ambient sounds) to prioritize memory and frame rate stability.

(3) Loading and Caching Strategy

Scenes with intensive audio loading require adjusted caching strategies. For example, voice audio is recommended to use **segmented loading** to avoid one-time loading of full story voice packs and reduce memory pressure.

# 2.5 Animation Resources

The memory footprint and runtime performance overhead of animation resources depend mainly on animation type selection, compression strategy configuration, and curve precision control. Improper settings easily lead to memory redundancy or extra CPU/GPU consumption and require targeted optimization based on project scenarios and device tiering. Key points:

(1) Animation Type Selection

The mainstream solution in Unity is the **Generic** animation type (based on the Mecanim system, with overhead in `Animators.Update`). Its multithreading support and resource utilization are better than the **Legacy** type (overhead in `Animation.Update`). However, this advantage is especially obvious for skeletal animations; simple animations (such as UI animations) may perform better with Legacy.

Humanoid characters can use the **Humanoid** type, which supports animation retargeting but requires compliance with humanoid bone specifications. Avoid using high-cost types unnecessarily.

(2) Animation Compression Strategy

Set **Anim. Compression** to **Optimal**. Unity will automatically select curve optimization algorithms (e.g., keyframe merging, value quantization) to minimize memory usage while preserving visual quality.

For animations with low precision requirements (e.g., background effects, secondary character motions), **KeyframeReduction** mode can be used with manual adjustment of the **Reduction Tolerance** parameter (recommended range: 0.01–0.1) to reduce redundant keyframes.

The default **Off** mode is generally not recommended, as animation data remains uncompressed and memory usage may double.

(3) Simplify Animation Content

Remove invalid curves (e.g., unused Scale curves, redundant bone animation channels), delete blank keyframes, or merge similar frames.

Shorten unnecessary animation duration. For mobile platforms, single animation memory is recommended to be controlled within **200 KB**. Complex animations can be split into multiple short clips and loaded on demand.

(4) Precision and Sampling Rate Control

Compress animation precision via API, such as using `AnimationUtility.SetAnimationClipSettings` to adjust frame rate (15–30 fps recommended for mobile; 60 fps is generally not advised).

For looping animations (e.g., breathing, idle), reduce keyframe density in loops and use interpolation to maintain smoothness.

Following Unity’s official optimization scheme, you can traverse animation curves in code and merge keyframes with differences below a threshold to further reduce data size.

Additional considerations based on actual project conditions:

(1) Animation Resource Reuse

Extract common animations (walk, attack, idle) as shared resources and reuse them via Animator Controller state machines to avoid duplicate similar clips.

Use animation retargeting to adapt one set of animations to multiple models and reduce redundancy.

(2) Trade-off Between Memory and Performance

Compression strategies (e.g., Optimal) may cause slight precision loss. Verify that animations for core characters and key skill effects meet expectations through real-device testing.

On mid-to-low-end devices, disable **Root Motion**, **IK**, and other features for secondary animations to reduce CPU computation pressure.

(3) Resource Detection and Filtering

Use the **Local Resource Detection Tool** to screen animations with excessive precision and redundant keyframes, focusing on resources with oversized single-frame data or mismatched duration.

Non-core animations exceeding **500 KB** should be re-optimized or split by artists.

(4) Tiering Strategy

Complex animations (multi-bone linkage, physics-driven animations) are recommended for tiered processing:

- High-end devices: full-precision version
- Mid-to-low-end devices: simplified version (fewer bones, lower frame rate)

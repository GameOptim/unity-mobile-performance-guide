# 2.8 Render Texture

## 2.8.1 Render Resolution

Some RT resources in the resource list reflect the current rendering resolution of the project. For projects with high GPU and rendering module pressure, reducing the rendering resolution on mid-to-low-end devices is a straightforward and effective tiering strategy. However, such adjustments affect GPU fragment computation pressure and bandwidth more than memory usage, which will be discussed in detail in the later GPU chapter.

![34](https://uwa-ducument-img.oss-cn-beijing.aliyuncs.com/GameOptim/2.8RenderTexture/34.png)

Attention should also be paid to other RT resources with excessively high resolution, especially those above 2048×2048. It is necessary to check whether such high precision is required, and consider using lower resolutions on low-end devices.

## 2.8.2 Anti-Aliasing

The AA multiplier of RT resources is displayed in the resource list. Enabling multi-sample AA increases RT memory usage exponentially and imposes additional pressure on the GPU. It is recommended to check whether AA is necessary, especially on mid-to-low-end devices, where it can be disabled.

![35](https://uwa-ducument-img.oss-cn-beijing.aliyuncs.com/GameOptim/2.8RenderTexture/35.png)

Specifically, 2× AA fails on some Huawei models: it causes performance overhead but provides no actual anti-aliasing effect.

## 2.8.3 Post-Processing

Many common post-processing RTs (such as Bloom, Blur) start sampling at 1/2 of the rendering resolution. You can change this to start sampling at 1/4 and reduce the number of downsampling passes to save memory and reduce post-processing rendering pressure.

![36](https://uwa-ducument-img.oss-cn-beijing.aliyuncs.com/GameOptim/2.8RenderTexture/36.png)

From a performance optimization perspective, it is even better to disable various post-processing effects tiered on mid-to-low-end devices. Discussions around common post-processing effects will be further expanded in the GPU section below.

## 2.8.4 RT in URP

When using URP, two additional RT resources, `_CameraColorTexture` and `_CameraDepthAttachment`, are created in memory as render targets. Enabling **CopyDepth** and **CopyColor** in the URP Camera settings additionally generates `_CameraDepthTexture` and `_CameraOpaqueTexture` as intermediate RTs. When these two RTs appear in the resource list, check whether CopyDepth and CopyColor are actually required; otherwise, disable them to avoid unnecessary waste.

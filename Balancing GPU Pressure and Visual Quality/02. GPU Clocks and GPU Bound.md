# 4.2 GPU Clocks and GPU Bound

The summary page of GPU Mode directly displays the **GPU Clocks** curve.

GPU Clocks is a value collected by GameOptim through **low-level hardware interfaces**, representing the **GPU clock cycles consumed per frame**, in **10,000 Cycles/frame**.

Multiplying this value by the **target frame rate** gives the **required GPU computing power per second** during runtime, which we call **real-time required performance**.

Each SoC has a **rated maximum frequency** set by the manufacturer at launch, representing its theoretical maximum clock cycles per second at full performance, in **MHz (1,000,000 Cycles/sec)**. We call this **theoretical maximum performance**.

Obviously:

**If real-time required performance > theoretical maximum performance of the device GPU**,

the hardware cannot meet the rendering demand, resulting in **longer execution time and lower frame rate**.

This can be summarized as a formula:

**Real-time GPU Clocks × Real-time Frame Rate = Real-time GPU Frequency**

During actual runtime, heavy GPU load also causes severe overheating, triggering **hardware thermal throttling** that reduces frequency. If rendering workload remains unchanged, the frame rate drops further.

GameOptim defines a high-pressure state **even if no frame drop occurs yet**:

when the GPU is forced to run at **high frequency** to finish work, resulting in high power consumption and overheating.

Frames meeting either condition are marked as **GPU Bound (pink)** in GameOptim, using the rule:

**Real-time GPU Clocks × Target Frame Rate ≥ GPU Rated Max Frequency × 80%**

As shown in the chart, the GPU Bound frame ratio reaches **93.09%**.

Clearly: **the higher the yellow GPU Clocks curve, the lower the blue frame rate curve**.

GPU pressure is undoubtedly the fatal bottleneck in this demo scene.

After more than a year of extensive testing and practice, GameOptim confirms that

**GPU Bound judged by this method is far more reliable than any other approach**.

A simple variation of the formula can directly guide **device tiering and optimization targets**.

Example:

A project selects **Mali‑G76** as the mid-tier baseline device (high market share, stable performance), targeting **stable 30 FPS**.

Its GPU rated max frequency = **720 MHz**.

Optimization target:

**GPU Clocks ≤ 720 MHz ÷ 30 = 24,000,000 Cycles/frame**

To control overheating, multiply by 80%:

**GPU Clocks ≤ 19,200,000 Cycles/frame**

In future development:

If new scenes, post‑processing, effects, or high‑poly models cause **GPU Clocks to exceed this threshold**,

rendering settings or assets **must be optimized** for this tier.

Once we locate GPU Bound areas, we enter **detailed problem diagnosis**.

GPU pressure generally comes from two sources:

**Vertex stage computation pressure** and **Fragment stage computation pressure**.
